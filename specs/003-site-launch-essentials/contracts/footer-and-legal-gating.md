# Contract: Footer Gating, Crawler Files, As-Is Freeze Verification

## Footer (`FR-LEG-001`)

`Footer.astro` renders a fixed structure — `<footer aria-label="Legal">` containing a `<ul>` of links — but its **contents** are conditional:

```ts
const privacy = await getLegalDocument("privacy");
const terms = await getLegalDocument("terms");
// Render a link only when the corresponding document resolved (not undefined).
```

**Contract**:
- If both are `undefined`, the footer element itself still renders (an empty or near-empty landmark) — it is not conditionally omitted, since `FR-LEG-001` requires it on every page regardless of legal-page shipping status.
- Every link present is a real `<a href>`, keyboard-reachable, with a visible focus state (Constitution Principle IX).
- The footer sits below all existing page content in DOM order and must not alter, overlap, or reflow anything above it (`FR-LEG-001`) — verified by `as-is-freeze.spec.ts` (see below), not just visually inspected.
- The footer does **not** duplicate Invest's existing contracting-entity line (`002` `FR-INV-012`) — it carries only "Privacy"/"Terms", nothing else.

## Privacy / Terms pages (`FR-LEG-002`, `FR-LEG-006`, `FR-LEG-007`)

`src/pages/privacy.astro` and `terms.astro` each:

1. Call `getLegalDocument(kind)`.
2. If `undefined` → the route itself should not be considered "shipped": do not link to it (the Footer contract above already ensures this), and the page, if requested directly, is out of this contract's scope to special-case — Astro will render whatever the component does with `undefined` data, so the component MUST guard and render nothing meaningful rather than throw (avoid a broken build) — return a 404-equivalent minimal state or redirect, decided at implementation time, but MUST NOT fabricate legal text as a fallback.
3. If present, render `body` as real headings (`<h2>` per `body[].heading`) and paragraphs, plus a visible "last updated" line using `sourceLastUpdated` if present, else `fetchedOn` labeled "Fetched \<date\>" (`FR-LEG-006`).

## `robots.txt` (`FR-SEO-007`)

Static, content-fixed contract (no template logic):

```text
User-agent: *
Allow: /

Sitemap: https://orbolo.com/sitemap.xml
```

## `sitemap.xml` (`FR-SEO-008`)

Generated by `@astrojs/sitemap` at build time from `astro.config.mjs`'s `site` + every static route Astro discovers, **filtered** to exclude `/404`. Privacy/Terms routes appear in the sitemap automatically once their pages exist as real routes — which only happens once `getLegalDocument()` resolves for them (their `.astro` files render real content, not a stub, only in that case) — so no separate sitemap-inclusion logic is needed beyond the existing `/404` filter; an unshipped legal page simply isn't a route the crawler discovers in the first place if its component early-returns/404s per the Privacy/Terms contract above. **Verify this assumption explicitly in `tasks.md`'s test task** — if Astro still emits a route file for an early-returning component, the sitemap filter needs to explicitly exclude `/privacy`/`/terms` too when their `LegalDocument` is absent, at generation time.

## As-Is Freeze verification (`SC-001`, `FR-GEN3-001`)

`tests/e2e/as-is-freeze.spec.ts` contract: for each of Home, Invest, Beef, Land, Contact, at 390px and 1440px:

1. Capture the page's DOM structure/text content **above** the new `<footer>` landmark, both before this feature's footer/meta changes exist (a recorded baseline, captured once at the start of implementation) and after.
2. Assert zero differences in that captured region.
3. The accent-color exception (constitution, 2026-09-30) means a *visual* (pixel/color) diff is expected wherever `#bfd55d` is newly applied to an existing fill — this test checks **structure and text content**, not color, since FR-GEN3-001 as amended permits color-only changes but nothing else. A separate, lighter visual spot-check (not full pixel-diff automation) during the `taste` pass covers whether the color application itself looks right — not this test's job.
